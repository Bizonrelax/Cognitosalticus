## Что такое семантика

Семантика — это учение о смысле, о значении. Когда говорят «семантическая сеть», имеют в виду сеть, в которой **связи между узлами несут смысл**. Не просто «А соединено с Б», а «А является причиной Б», «А входит в состав Б», «А противоречит Б». Тип связи важен, потому что он меняет смысл всей конструкции. Ты хочешь именно этого: задавать тип каждой связи. Поэтому твоя программа — семантическая сеть, а не просто граф.

# Cognitosalticus — техническое задание

## 1. Общие сведения

**Название проекта:** Cognitosalticus.

**Назначение:** локальная программа для ручного построения семантической сети из сущностей («нейронов»), связанных типизированными связями и объединённых в пересекающиеся, бесконечно вложенные кластеры.

**Целевая платформа:** Windows 11 (x64). Допускается запуск на Windows 10.

**Принципиальное ограничение:** никаких баз данных. Всё хранится в файлах на диске. Пользователь сам выбирает папку хранения — на HDD, SSD, флешке, внешнем диске.

**Визуализация сети отсутствует.** Интерфейс — формы, списки, поля ввода.

## 2. Термины и определения

**Нейрон** — сущность сети. Хранится в отдельном файле. Имеет: идентификатор, имя, текстовое поле произвольного объёма, набор свойств, одну папку с файлами, набор исходящих связей, набор кластеров, в которые входит.

**Свойство нейрона** — пара «ключ — значение» с типом. Количество свойств: от нуля до любого. Свойства можно добавлять и удалять. Свойства используются для автоматического поиска связей между нейронами (по совпадению ключей и значений) и для ручной фильтрации.

**Связь (отросток)** — направленная связь от одного нейрона к другому. Имеет тип, необязательную заметку и идентификатор. Тип связи задаётся пользователем; список типов пополняется вручную. Примеры типов: «влияет на», «является частью», «противоречит», «следует из».

**Кластер** — именованная группа, которая может содержать и нейроны, и другие кластеры одновременно. Один нейрон может входить в любое число кластеров. Один кластер может входить в любое число других кластеров. Вложенность не ограничена.

**Сеть** — вся совокупность нейронов, связей и кластеров в выбранной папке хранения.

**Папка нейрона** — папка на диске, принадлежащая нейрону. Может содержать любые файлы. Путь к папке задаётся при создании нейрона.

## 3. Концептуальная модель

### 3.1. Сущности

- Нейрон (Neuron)
- Связь (Connection)
- Кластер (Cluster)
- Тип связи (ConnectionType)
- Свойство (Property)

### 3.2. Отношения

- Нейрон → Нейрон: направленная связь с типом (0..∞).
- Нейрон → Кластер: членство (0..∞).
- Кластер → Кластер: вложенность (0..∞).
- Кластер → Нейрон: членство (0..∞).
- Нейрон → Свойство: владение (0..∞).
- Связь → Тип связи: ссылка (1).

### 3.3. Принципы

1. Каждый нейрон — отдельный файл. Каждый кластер — отдельный файл. Каждый тип связи — запись в общем файле типов.
2. Связи хранятся внутри файла нейрона-источника (исходящие связи). Входящие связи вычисляются сканированием.
3. Кластеры хранят только идентификаторы участников, не копии данных.
4. Все файлы — человекочитаемый JSON в кодировке UTF-8.
5. Папка хранения переносима: копирование папки на флешку и обратно не ломает сеть.

## 4. Функциональные требования

### 4.1. Нейрон

**4.1.1. Создание.** Пользователь нажимает «Создать нейрон». Программа запрашивает имя (обязательно) и путь к папке (обязательно). Создаётся файл нейрона и папка, если её нет.

**4.1.2. Текстовое поле.** Произвольный объём текста. Автосохранение с задержкой (например, через 2 секунды после последнего изменения) и по кнопке «Сохранить».

**4.1.3. Свойства.** Список пар «ключ — значение». Каждое свойство имеет тип: строка, число, дата, логическое, ссылка. Добавление, удаление, редактирование. Ключи могут повторяться.

**4.1.4. Папка.** Одна папка на нейрон. Путь можно изменить. При изменении пути файлы не переносятся автоматически — программа предупреждает, что папка будет только перепривязана. Внутри папки можно открыть проводник Windows.

**4.1.5. Просмотр.** Список всех нейронов с поиском по имени. Клик открывает карточку нейрона.

**4.1.6. Редактирование.** Имя, текст, свойства, папка.

**4.1.7. Удаление.** Мягкое удаление: нейрон помечается как удалённый и перемещается в папку `trash/` внутри хранилища. Восстановление возможно. Окончательное удаление — отдельной командой с подтверждением.

### 4.2. Связи

**4.2.1. Создание.** Из карточки нейрона-источника: выбрать нейрон-цель (поиском по имени), выбрать тип связи, добавить заметку.

**4.2.2. Типы связей.** Пользователь ведёт список типов. Каждый тип: имя, описание, цвет метки (для списков). Типы можно добавлять, переименовывать, удалять (с проверкой, что тип не используется, или с заменой на другой тип).

**4.2.3. Просмотр.** В карточке нейрона — два списка: «исходящие» и «входящие». Входящие вычисляются сканированием всех нейронов при загрузке.

**4.2.4. Редактирование.** Изменить тип, заметку, цель.

**4.2.5. Удаление.** Удаление связи из источника.

**4.2.6. Ограничения.** Связь направленная. Кратные связи между одной парой разрешены, если различаются типом или заметкой.

### 4.3. Кластеры

**4.3.1. Создание.** Имя, описание. Создаётся файл кластера.

**4.3.2. Состав.** В кластер можно добавить нейрон (из карточки нейрона или из карточки кластера) и другой кластер. Удаление участника — из карточки кластера.

**4.3.3. Вложенность.** Кластер может содержать кластеры. Циклическая вложенность запрещена: программа проверяет при добавлении и отказывает, если образуется цикл.

**4.3.4. Множественное членство.** Один нейрон — в любом числе кластеров. Один кластер — в любом числе кластеров.

**4.3.5. Просмотр.** Список кластеров с поиском. Карточка кластера: имя, описание, список нейронов-участников, список кластеров-участников, список кластеров, в которые входит данный кластер.

**4.3.6. Удаление.** Мягкое удаление в `trash/`. При окончательном удалении кластера его участники не удаляются, только членство.

### 4.4. Поиск и фильтрация

**4.4.1. Поиск по нейронам.** По имени (подстрока), по тексту (полнотекстовый поиск по всем файлам), по свойствам (ключ = значение, ключ содержит значение).

**4.4.2. Фильтрация.** По кластеру (показать все нейроны, входящие в кластер, включая вложенные кластеры). По типу связи (показать нейроны, у которых есть связь данного типа). По наличию папки.

**4.4.3. Сортировка.** По имени, по дате создания, по дате изменения.

### 4.5. Автоматическое обнаружение связей

**4.5.1. По совпадению свойств.** Программа находит пары нейронов, у которых совпадает ключ свойства и значение. Показывает список «возможных связей» с указанием, по какому свойству совпадение. Пользователь подтверждает или отклоняет. Подтверждение создаёт связь выбранного типа.

**4.5.2. По совпадению имён.** Нечёткое совпадение имён (например, расстояние Левенштейна ниже порога). Показывает возможные связи.

**4.5.3. Ручной запуск.** Автопоиск запускается кнопкой, не автоматически, чтобы не тормозить интерфейс.

### 4.6. Операции с сетью

- Создание, чтение, редактирование, удаление нейрона.
- Создание, редактирование, удаление связи.
- Создание, редактирование, удаление кластера.
- Добавление и удаление участников кластера.
- Поиск и фильтрация.
- Автопоиск связей.
- Импорт нейрона из JSON-файла.
- Экспорт нейрона в JSON-файл.
- Экспорт всей сети в один JSON-файл (для резервной копии).
- Импорт всей сети из JSON-файла.
- Проверка целостности: битые ссылки, отсутствующие папки, циклическая вложенность, связи на удалённые нейроны.
- Восстановление из `trash/`.
- Резервное копирование: копирование всей папки хранилища в указанное место с меткой времени.

Каждое сохранение: запись во временный файл `<name>.tmp`, затем атомарное переименование в целевой файл. Это защищает от потери данных при выключении питания.

## 10. Открытые вопросы

Эти пункты в твоём описании пока не определены. Их надо решить до этапа реализации.

1. **Что именно считается «свойством»?** Только пара «ключ — значение», или свойство может быть ссылкой на другой нейрон? Если ссылка — это уже связь, и надо различать свойство-ссылку и связь.
2. **Может ли папка нейрона лежать вне папки хранилища?** Если да — как вести себя при переносе хранилища на флешку? Перепривязывать вручную или копировать папки внутрь?
3. **Нужна ли история изменений?** Например, «нейрон изменён 5 раз, можно откатиться к версии от вчера». Это усложняет хранение (нужны версии файлов).
4. **Нужны ли теги?** Отдельно от кластеров. Тег — плоская метка, кластер — иерархическая структура. Это разные вещи.
5. **Что делать с циклической вложенностью кластеров?** Запрещать (как в ТЗ) или разрешать с предупреждением?
6. **Нужен ли экспорт в CSV или другие форматы?** Или только JSON?
7. **Нужна ли синхронизация между компьютерами?** Если да — это отдельная большая тема (git, облако, ручное копирование).
8. **Кто пишет программу?** Ты сам или с помощью? Это влияет на выбор технологий (Spring Boot vs JavaFX vs что-то ещё).
